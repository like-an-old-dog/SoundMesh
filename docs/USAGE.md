## 0. 内置使用教程

Windows 与安卓首页顶部都有「使用教程」，**不需要先开始融合**：

- **Windows**：打开程序目录里的 `guide.html`。这个文件必须和 `SoundMesh.exe` 放在一起，缺失时会提示重新完整解压。
- **Android**：应用内离线阅读，不联网也能看。
- **iPhone 网页监听页**：同名入口会直接跳到 Safari 操作那一章，关闭教程回到混音台。

七章分别是：第一次把手机和电脑连起来 / 扫码、手动配对和第三台设备 / 把耳机切到另一台设备 / 选对音量滑杆 / 卡顿时怎样选缓冲 / 用 iPhone 的 Safari 监听 / 搜不到设备、已连接却无声。

## 1. 准备网络

1. 所有参与设备接入**同一个局域网**，并且能互相访问。访客 Wi-Fi、开启 AP 隔离的热点、部分企业网络会阻断设备互访，此时发现和音频都会失败。
2. 放行端口：
   - **UDP 49633** —— 设备发现（广播）
   - **TCP 49632** —— 音频、配对与监听接管
   - **TCP 49634** —— iPhone 网页桥接（仅浏览器监听时需要）
3. Windows 首次运行会弹出防火墙提示，请允许**专用网络**访问。当初点了取消的话，要在「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里手动放行 `SoundMesh.exe`。

> 链路是明文局域网传输。配对码和音频都没有加密，**请只在可信网络使用**，不要把 49632/49633 映射到公网。

## 2. 开始融合（双向）

1.1 只有一种会话模式：**开始融合 = 同时发送本机声音 + 接收其他设备声音**。

1. 在**每台**设备上点「开始融合」。
   - Android 会弹出系统录屏/录音授权（`MediaProjection`），确认后才开始采集。该授权只用于采集允许共享的媒体声音。
   - Windows 会启动独立的 `SoundMeshCapture.exe` 做进程隔离采集，因此 `SoundMesh.exe` 与 `SoundMeshCapture.exe` **必须在同一目录**；缺少它在启动时会报错。
2. 会话启动后界面从「准备融合」变为「设备融合中」，三个页签（混音台 / 设备连接 / 输出设置）由灰变可用。
3. 结束会话点「结束融合」。Windows 会在结束时把「本机应用」的音量恢复原状。

> Windows 的进程隔离采集需要 build 20348+（通常是 Windows 11）。低版本系统会在启动时提示失败。

## 3. 配对设备

设备连接页有两张卡片：

- **连接本机**：显示本机的配对二维码、IP 选择、8 位配对码与已接入数量，以及「邀请 iPhone 网页监听」。
- **附近设备**：扫描同一局域网的其它设备并连接。

配对方式任选：

1. **附近设备**：点「刷新」→ 选中对端 → 「连接所选设备」。首次需要输入对方界面上显示的 **8 位配对码**。
2. **扫码**：在接收方点「显示配对二维码」，对方用手机声汇扫码；Windows 也可以点「读取二维码图片」选中对方另存的二维码。
3. **手动配对**：点「手动配对」展开输入框，直接填对端局域网 IP 与配对码。多网卡、VPN 干扰发现时最可靠。

配对成功后同一台设备会被记住（Windows 存于 `HKCU\Software\SoundMesh\Pairing`），下次直接连接即可。**一次配对同时建立两个方向**，不需要再反向配一次。

三台及以上设备请**逐对连接**：A–B、A–C、B–C。每台设备的混音只包含它直连的对端。

## 4. 耳机与监听

**耳机接在哪台，就在哪台接管监听。**

1. 在该设备打开「输出设置」页。
2. 点「把监听切到本机」：本机开始输出远端混音，并通知所有已连接的 Beta 对端暂停监听，避免同一份声音在两副耳机里重复。
3. 勾选框「在本机监听」反映本机是否正在输出；「把监听切到本机」会把它勾上。

实际蓝牙音频路由由系统或耳机的多点连接策略决定，必要时在系统输出列表里手动选中耳机。设备之间**不支持直接蓝牙音频传输**，蓝牙耳机只能作为系统输出。

## 5. 调音

### 5.0 播放缓冲怎么选

「输出设置 → 播放缓冲」有 6 档：

| 档位 | 适用场景 |
| --- | --- |
| 同步 · 100 ms | 网络很稳、追求更低延迟；抖动时会更容易听到缺音 |
| **同步 · 150 ms（默认）** | 一般家庭 Wi-Fi 的平衡点 |
| 同步 · 200 ms | 网络波动大、或跨设备混音明显错位时 |
| 灵敏 · 25 ms / 均衡 · 70 ms / 稳定 · 90 ms | 仅作用于**旧版本设备与 iPhone 网页**的独立缓冲 |

同步档位下，设备卡片显示的是「已校时 · 立体声」，缓冲一栏是时间轴上前方还有多少毫秒待播，断流一栏是时间轴缺音次数。兼容连接显示「兼容模式 · 独立缓冲」。

### 5.1 混音台

| 滑杆 | 作用 |
| --- | --- |
| 每台远端设备 | 该设备声音在当前监听端的音量，附「静音」与电平条 |
| **其他设备合计** | 所有远端通道的总音量 |
| **本机发送** | 本机发出去的音量，影响所有接收方听到的内容 |
| **本机应用**（仅 Windows） | 按比例压低默认输出上**其他应用**的音量，跳过声汇自己的会话 |

**「本机应用」的行为细节**：它按会话记录每个应用调整前的基准音量，只在值与上次设置一致时恢复，所以期间你手动改过的应用音量不会被覆盖。结束融合会自动恢复；异常退出后需要手动调回。它只作用于默认播放设备。

**「本机发送」的细节**：这是发送侧增益，只影响出站信号，不改变你自己的混音。测试里验证了它能压低出站而远端混音不变、也能把出站压到静音。

### 5.2 Windows 音量小窗

- `Ctrl+Alt+M` 显示或收起，`Esc` 收起；被其他程序占用时点主窗口的「音量小窗」。
- 下拉列表可选：远端混音总音量、本机应用、本机 · 发给其他设备、以及每一台已连接的设备。
- 「静音 / 恢复」会记住静音前的值。
- 小窗与主界面滑杆双向同步。

### 5.3 Android 系统媒体卡片

- 下拉通知栏展开声汇的媒体卡片，**拖动进度条 = 调远端混音总音量**，卡片标题显示百分比。
- 轻点卡片打开「声汇音量」面板，可分别调节：本机 · 发给其他设备、本机 · 系统媒体输出、远端混音总音量、各远端设备。
- 不同厂商的紧凑布局可能隐藏进度条，点开卡片即可；Android 13 及以上需允许通知。

> **本机 · 系统媒体输出**调的是系统媒体音量，它同时影响声汇自己的播放。想要「扬声器不响、采集电平不变」，请把发送端媒体路由到闲置的有线耳机或 USB 声卡，而不是靠这条滑杆。

## 6. iPhone 浏览器监听

不用装 App、不用签名，Safari 里直接听。前提是电脑已「开始融合」。

1. 电脑「设备连接」页点「邀请 iPhone 网页监听」，弹出二维码。
2. 用 iPhone **系统相机**扫码，在弹窗里选 Safari 打开，点「开始监听」。
3. 网页里可以添加**另一台**已开启融合的设备（填 IP 与 8 位配对码），逐路调音或静音。
4. 结束电脑端融合会关闭网页会话；重新开启后需要扫新的二维码（令牌每次启动都会变）。

注意事项：

- 网页使用局域网 HTTP 与 WebSocket（TCP 49634），不是 HTTPS。局域网内的取舍，请不要在不可信网络使用。
- 建议先保持 Safari 在前台，等播放稳定后再切后台；iOS 可能挂起后台页面的音频。
- 令牌通过 URL 的 `#fragment` 传递，不进入请求行或日志；接口需要 `Authorization: Bearer`。
- **验证状态**：网页播放链路已在桌面 Chromium 上通过（含逐声道静音与暂停）。实体 iPhone Safari 与耳机听感仍待验证。
- 想发送 iPhone 自己的应用声音（而不只是收听），需要原生版，见 [src/ios/README.md](../src/ios/README.md)。

## 7. 采集的细节

### 7.1 Windows

| 方式 | 实现 |
| --- | --- |
| 进程隔离（1.1 默认） | 独立进程 `SoundMeshCapture.exe` 用 `ActivateAudioInterfaceAsync(VIRTUAL_AUDIO_DEVICE_PROCESS_LOOPBACK)` + `PROCESS_LOOPBACK_MODE_EXCLUDE_TARGET_PROCESS_TREE` 采集，排除声汇自身进程树，PCM 经 stdout 管道回主程序 |

- 采集跟随系统默认播放设备；切换默认设备后建议结束融合再重新开始。
- 普通发送/接收在 Windows 10 上可用，但「开始融合」默认走进程隔离，需要 build 20348+。

### 7.2 Android

- 使用 `MediaProjection` + `AudioPlaybackCapture`，只能采集**允许共享的媒体声音**；受保护内容（部分流媒体、DRM 视频）与通话声音采集不到。
- 前台服务持有 Wi-Fi 高性能锁与 `PARTIAL_WAKE_LOCK`，避免息屏后被系统挂起；仍建议允许后台运行。
- 需要 Android 10（API 29）及以上。

## 8. 故障排查

| 现象 | 可能原因与处理 |
| --- | --- |
| 「附近设备」始终为空 | 不同子网 / AP 隔离 / 防火墙拦截 UDP 49633。改用「手动配对」填 IP。 |
| 能发现但连接超时 | 防火墙拦 TCP 49632；或对方已结束融合。 |
| 提示"配对失败，请检查配对码" | 配对码错，或两端版本不匹配（0.1 与 0.2+ 不互通）。 |
| 列表里地址明显不对 | 电脑多网卡。发现回复取来源地址，VPN/虚拟网卡会干扰；设备连接页可手动改选地址。 |
| 开机就提示融合启动失败 | `SoundMeshCapture.exe` 不在同目录，或系统版本低于 20348。 |
| 声音断续 | 切「稳定 · 90 ms」；避开 2.4 GHz 拥塞；关闭同网段的大流量下载。 |
| 两边都有声音、听起来重复 | 两端都在监听。只需在耳机所在设备点「把监听切到本机」。 |
| 明明在监听却听不到远端 | 检查「在本机监听」是否勾选；以及「其他设备合计」是否为 0。 |
| 电脑突然没声音 | 看「本机应用」是否被拉低（结束融合会恢复）；或系统静音。 |
| 发送端换了 IP 后连不上 | 移除旧通道，从「附近设备」重新连接。程序会自动重试 1/2/4/8 秒，但不跟随 IP 变化。 |
| 多台设备声音有先后（错位） | 两端是否都已升级到 1.2；旧版本会走独立缓冲，天然不对齐。再看缓冲是否被设成同步档。 |
| 同步档下经常缺音 | 把同步缓冲调到 200 ms，或改回「均衡 · 70 ms」用独立缓冲。 |
| Android 采集到的是静音 | 该应用可能禁止被录制（受保护内容/DRM），或未走媒体输出。换一个音源测试。 |
| iPhone 页面空白 | 电脑端融合是否已结束；二维码是否过期（重新点一次「邀请 iPhone 网页监听」）。 |
