## 1. 准备网络

1. 所有参与设备接入**同一个局域网**，并且能互相访问。访客 Wi-Fi、开启 AP 隔离的热点、部分企业网络会阻断设备互访，此时发现和音频都会失败。
2. 放行端口：
   - **UDP 49633** —— 设备发现（广播）
   - **TCP 49632** —— 音频与配对握手
   - **TCP 49634** —— iPhone 网页桥接（仅在用浏览器监听时需要）
3. Windows 首次运行会弹出防火墙提示，请允许**专用网络**访问。如果当初点了取消，需要在「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里手动放行 `SoundMesh.exe`。

> 链路是明文局域网传输。配对码和音频都没有加密，**请只在可信网络使用**。不要把 49632/49633 映射到公网。

## 2. 用耳机监听（单向）

这是最常用的模式：一台设备当接收端，其他设备当发送端。

### 2.1 在接收端

1. 打开「耳机监听」（Windows）或接收页（Android）。
2. 点「刷新」扫描附近设备，或者点「手动配对」直接填 IP。
    - Windows 还可以点「读取二维码图片」，选中对方界面上「显示配对二维码」另存的图片。
3. 从「附近设备」里选发送端，点「连接所选设备」。首次需要输入对方的 **8 位配对码**。
4. 连接成功后，混音台出现一条设备卡片：音量滑杆、静音按钮、当前缓冲时长、断流次数。
5. 本机其他应用的声音**不受影响**，仍由系统直接播放。

### 2.2 在发送端

1. 打开「共享声音」页，点「开始共享」。
2. Android 会弹出系统录屏/录音授权（`MediaProjection`），确认即可；授权仅用于采集允许录制的媒体声音。
3. Windows 可以选择「共享时静音电脑当前输出」，见下一节。
4. 发送端界面会显示 8 位配对码，点「显示配对二维码」可让对方扫码。

### 2.3 配对记忆

首次连接后，配对码按设备 ID 记在接收端（Windows 存于 `HKCU\Software\SoundMesh\Pairing`）。以后同一台设备再次出现，直接连接即可，无需重输。

发送端如果被重装，或清除了应用数据，会生成新的配对码，需要重新输入一次。

## 3. 共享本机声音的细节

### 3.1 Windows

- **采集方式**：`SoundMeshCapture.exe` 以独立进程运行 WASAPI 进程回环采集，并排除声汇自身的进程树。因此声汇播放的混音不会被重新采集发回网络。
- **必须是两个文件**：`SoundMesh.exe` 与 `SoundMeshCapture.exe` 放在同一目录。整个 zip 解压后再运行，不要只把 exe 拖出来。
- **「共享时静音电脑当前输出」**：勾选后，程序临时静音当时的系统播放设备（这样本机扬声器不会和远端重复出声），正常停止时恢复原静音状态。异常退出（崩溃、强杀）后静音不会自动恢复，需要在系统音量面板里手动取消。
- **系统要求**：进程回环采集需要 Windows build 20348 及以上（通常是 Windows 11）。Windows 10 上普通发送与接收可用，但"共享时静音本机输出"与双向模式不可用。
- **双屏/多声卡**：采集跟随系统默认播放设备。切换默认设备后建议重新开始共享。

### 3.2 Android

- 使用 `MediaProjection` + `AudioPlaybackCapture`，只能采集**允许录制的媒体声音**。受保护内容（部分流媒体、DRM 视频）和通话声音受系统限制，采集不到。
- **无法只静音其他应用的本地扬声器**：普通 Android 应用做不到"把别的声音的扬声器静音、同时保留完整采集音量"。
  - 折中办法一：调低媒体音量，在接收端试听。如果两端同时变小，说明采集电平也跟着降了。
  - 折中办法二（推荐）：把发送端的媒体输出路由到闲置的**有线耳机或 USB 声卡**，这样扬声器不响、采集电平不变。
- 共享时前台服务会持有 Wi-Fi 高性能锁与 `PARTIAL_WAKE_LOCK`，避免息屏后被系统挂起。仍然建议保持屏幕常亮或允许后台运行。
- 需要 Android 10（API 29）及以上。

## 4. 双向空间 Beta

双向模式下，一台设备同时发送自己的声音、接收并对端的声音。

### 4.1 建立

1. 两台设备（或更多）都进入「双向空间 Beta」页。
2. 在任一端选择另一台设备并配对。握手会带上反向配对码，两台自动建立**双向**连接。
3. 三台设备请**逐对连接**：A–B、A–C、B–C。每台都能独立混合其余设备的来源。

### 4.2 耳机在哪台，就在哪台听

- 在耳机所接的设备点「把监听切到本机」：本机开启远端混音，并通知所有已连接的 Beta 对端暂停监听。这样同一份声音不会在两副耳机里重复。
- 切换后，原应用的本地播放仍由系统管理。**实际蓝牙音频路由由系统或耳机的多点连接策略决定**，必要时在系统输出列表里手动选中耳机。

### 4.3 限制

- 设备之间通过 IP 通信；蓝牙耳机只能作为系统输出，**不支持设备间直接蓝牙音频传输**。
- 三台实体设备、蓝牙多点耳机接管、真实声学延迟仍需实机验证。
- 如果接收端提示"对端未开启双向模式"，说明对方仍在普通共享/监听模式，需要先进入双向页。

## 5. iPhone 浏览器监听

不用安装 App、不用签名，Safari 里直接听。前提是电脑已经能共享声音。

1. Windows「共享声音」页点「iPhone 浏览器监听」，弹出二维码。
2. 用 iPhone **系统相机**扫码，在弹窗里选择用 Safari 打开，点「开始监听」。
3. 网页里可以添加**另一台**已开启共享的安卓或 Windows 设备（填 IP 与 8 位配对码），逐路调音或静音。
4. 停止电脑共享会结束网页会话；重新开启后需要扫新的二维码（令牌每次启动都会变）。

注意事项：

- 网页使用局域网 HTTP 与 WebSocket（TCP 49634），不是 HTTPS。这是局域网内自签方案的取舍，请不要在不可信网络使用。
- 建议先保持 Safari 在前台，等播放稳定后再切后台；iOS 可能挂起后台页面的音频。
- 桥接的令牌通过 URL 的 `#fragment` 传递，不会出现在 HTTP 请求头或服务器日志里；接口需要 `Authorization: Bearer` 头。
- **验证状态**：网页播放链路已在桌面 Chromium 上通过（含逐声道静音与暂停）。Windows 的 WebKit 测试运行时缺少 `Web Audio`，所以 **iPhone Safari 真机与耳机听感仍待验证**。
- 想发送 iPhone 自己的应用声音（而不只是收听），需要原生版，见 [src/ios/README.md](../src/ios/README.md)。

## 6. 音量与快捷操作

### 6.1 Android 通知栏

接收或双向模式下，通知栏会出现三个按钮：**−5%**、**静音／恢复**、**+5%**。它们与应用内总音量同步，**只作用于声汇混音**，不影响系统其他应用。

- Android 13 及以上需要授予通知权限，否则看不到按钮。
- 静音后「恢复」会回到静音前的百分比。

### 6.2 Windows 热键

- 运行期间按 `Ctrl+Alt+M` 显示或收起音量小窗，`Esc` 收起。
- 如果快捷键被其他程序占用，点主窗口的「音量小窗」按钮。
- 小窗与主窗口的总音量滑杆双向同步。

### 6.3 混音台

- **总音量**：作用于合成的混音输出。
- **每路音量 / 静音**：只影响对应来源。
- **缓冲档位**：灵敏 25 ms / 均衡 70 ms（默认）/ 稳定 90 ms。切换会立即应用到所有通道。
- **设备卡片**：显示断流次数与当前接收队列中积累的音频时长（不是端到端延迟）。

## 7. 故障排查

| 现象 | 可能原因与处理 |
| --- | --- |
| 「附近设备」始终为空 | 不同子网 / AP 隔离 / 防火墙拦截 UDP 49633。改用「手动配对」填 IP 试试。 |
| 能发现但连接超时 | 防火墙拦 TCP 49632；或对方已停止共享。 |
| 提示"配对失败，请检查配对码" | 配对码错，或两端版本不匹配（0.1 与 0.2+ 不互通）。 |
| 列表里地址明显不对 | 电脑有多块网卡。发现回复取的是来源地址，VPN/虚拟网卡会干扰。共享页可手动改选地址；接收端也可手动填 IP。 |
| 声音断续 | 切「稳定 · 90 ms」；靠近路由器、避开 2.4 GHz 拥塞；关闭同网段的大流量下载。 |
| 延迟越用越大 | 不应发生——积压时会丢弃旧样本。若确实出现，检查发送端是否在暂停后恢复（重新开始共享）。 |
| 电脑突然没声音 | 检查是否勾选了「共享时静音电脑当前输出」且程序异常退出。去系统音量面板取消静音。 |
| 发送端换了 IP 后连不上 | 移除旧通道，从「附近设备」重新选择。程序会自动重试 1/2/4/8 秒，但不会自动跟随 IP 变化。 |
| Android 采集到的是静音 | 应用可能禁止被录制（受保护内容/DRM），或该应用未走媒体输出。换一个音源测试。 |
| iPhone 页面打开是空白 | 电脑端共享是否已停止；二维码是否过期（重新点「iPhone 浏览器监听」）。 |
